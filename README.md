# Pythoncha（ぱいそんちゃ）

**北九州弁で書ける、Pythonベースの実験的プログラミング言語。**

Pythoncha は、北九州弁の語感や文法をプログラミング構文として取り込めないか試す、小さな言語実験です。

単に `print` を「表示」に置き換える日本語化ではなく、**「〜っちゃ」「〜けん」「〜やったら」など、方言の話し方そのものを構文にする**ことを目指します。

> 現在は構想段階です。方言表現・文法・実装方式はすべて provisional（仮）です。

## こんなコードを書きたい

```text
名前 = "山田"

もし 名前 が "山田" やったら
    "本人っちゃ" って言う
ちがったら
    "誰なん？" って言う
おわり
```

将来的には、たとえばこんな表現も検討します。

```text
雨が降っとるけん
    傘を持っていく

3回
    "まだやるん？" って言う
おわり
```

上の例は仕様ではありません。北九州弁として自然か、プログラミング構文として読みやすいかを見ながら決めていきます。

## 基本方針

- **北九州弁であることに意味がある言語**にする
- 方言を英語キーワードの単純な置換にしない
- 最初は小さく、実際に動くものを優先する
- Python を実行基盤として利用し、ゼロからVMやコンパイラを作ることは当面しない
- 読んで面白く、書いて遊べることを大事にする
- 「ネタ言語」で終わってもよいが、CLIから普通に実行できる程度には実用品として整える
- 方言の誇張や不自然な“なんちゃって北九州弁”にならないよう、表現は継続的に見直す

## 想定アーキテクチャ

初期版は、Pythoncha のソースコードを Python に変換して実行するトランスパイラ方式を想定しています。

```text
hello.cha
   ↓
Pythoncha parser / transpiler
   ↓
Python code
   ↓
Python runtime
```

最初の PoC では単純な行ベース変換でもよいものとし、文法が固まってきた段階で tokenizer / parser / AST の導入を検討します。

## CLI のイメージ

```bash
pythoncha hello.cha
```

将来的には、

```bash
pythoncha run hello.cha
pythoncha check hello.cha
pythoncha --version
```

のようなCLIも検討します。

拡張子の第一候補は `.cha` です。

## 言語設計で考えたいこと

### 1. 方言をどこまで文法にするか

候補例：

- 「〜やったら」: 条件
- 「〜けん」: 理由・条件・前提
- 「〜っちゃ」: 断定、出力、文末表現
- 「〜と？」: 真偽確認や問い合わせ

自然言語としての意味とプログラム上の意味が無理なく一致することを優先します。

### 2. 曖昧さを許すか

自然な日本語・方言に近づけるほど曖昧さが増えます。

Pythoncha では、

- 厳密な構文だけを受け付ける
- 表記ゆれをある程度許容する
- “自然文っぽさ”と“機械的な明確さ”の中間を狙う

などの選択肢を比較します。

### 3. Python との距離

初期版では Python をバックエンドとして利用しますが、Python の全機能を方言化することは目的にしません。

Pythoncha 独自の小さな言語として成立させ、必要に応じて Python の機能へ橋を架ける方向を想定しています。
