# Pyccha（ぱいっちゃ）

**北九州弁で書ける、Pythonベースの実験的プログラミング言語。**

Pyccha は、北九州弁の語感や文法をプログラミング構文として取り込めないか試す、小さな言語実験です。

単に `print` を「表示」に置き換える日本語化ではなく、**「〜っちゆう」「〜やったら」「〜よりでかいん」など、方言の話し方そのものを構文へどう落とせるか**を試します。

> 現在は v0.1 の最初の parser / transpiler を実装した段階です。方言表現・文法・実装方式はまだ変更される可能性があります。

## いま動くコード

```text
名前 = "山田"

もし 名前 == "山田" やったら
    "本人っちゃ" っちゆう
ちごうたら
    "誰なん？" っちゆう
おしまい
```

大小比較は、たとえば次のように書けます。

```text
年齢 = 22

もし 年齢 が 20 よりでかいん やったら
    "大人やん" っちゆう
おしまい
```

`が` など独立した文法トークンは、日本語識別子と lexer が区別できるよう空白で分けます。

回数ループは次のような形です。

```text
3回くりかえす
    "まだやるん？" っちゆう
おしまい
```

上の構文は v0.1 の現在の実装境界です。自然文を何でも解釈する言語にはせず、少数の厳密な構文として作ります。

## 使ってみる

Python 3.10 以上を使います。

```bash
python -m pip install -e ".[test]"
```

同梱のサンプルを実行します。

```bash
pyccha examples/snack.cha
```

出力:

```text
シロヤ
シロヤ
シロヤ
```

変換後の Python だけを見ることもできます。

```bash
pyccha --emit-python examples/snack.cha
```

テスト:

```bash
pytest -q
```

構文エラーでは、Lark の位置情報を使って行・列と周辺コードを表示します。

## 基本方針

- **北九州弁であることに意味がある言語**にする
- 方言を英語キーワードの単純な置換にしない
- 最初は小さく、実際に動くものを優先する
- Python を実行基盤として利用し、ゼロからVMやコンパイラを作ることは当面しない
- 読んで面白く、書いて遊べることを大事にする
- 「ネタ言語」で終わってもよいが、CLIから普通に実行できる程度には実用品として整える
- 方言の誇張や不自然な“なんちゃって北九州弁”にならないよう、表現は継続的に見直す
- 方言化すると不自然になる演算は `=`、`==`、`!=` などの記号を残してよい

## 現在のアーキテクチャ

Pyccha のソースコードを Lark で parse し、小さな AST を経由して Python に変換して実行します。

```text
hello.cha
   ↓
Lark grammar / parser
   ↓
Pyccha AST
   ↓
Python transpiler
   ↓
Python runtime
```

v0.1 の block は `おしまい` で明示的に閉じるため、最初の実装では Python のような INDENT / DEDENT 処理を持ちません。Lark の位置情報は AST に保持し、診断へ使える形にしています。

## CLI

現在の最小 CLI:

```bash

pyccha --emit-python hello.cha
```

`python -m pyccha hello.cha` でも実行できます。


## v0.1 の構文方針

現時点では次を最初の実装境界とします。

- 出力: `<式> っちゆう`
- 代入: `<名前> = <式>`
- 条件: `もし <条件> やったら`
- else: `ちごうたら`
- block終端: `おしまい`
- 回数ループ: `<整数>回くりかえす`
- 等値 / 非等値: `== / !=`
- 大小比較: `〜よりでかいん / 〜よりこまいん`
- AND / OR / NOT: `それと / か / やないん`
- コメント: `#`

論理演算の優先順位は、比較・原子 → `やないん` → `それと` → `か` の順です。

`やけん`、構文としての `っちゃ`、`ほんとやん / うそやん` は、北九州弁としての面白さは残しつつ、v0.1 の予約語・真偽値リテラルにはしません。

詳しい判断理由は [`docs/design/grammar-v0.1.md`](docs/design/grammar-v0.1.md) と [`docs/design/examples-v0.1.md`](docs/design/examples-v0.1.md) にまとめています。

## 言語設計で考えたいこと

### 1. 方言をどこまで文法にするか

Pyccha では、方言らしい語を見つけたからといって必ず予約語にしません。

たとえば、

- `〜やったら`: v0.1 の条件接続へ使う
- `〜っちゆう`: 発話の語感を標準出力へ使う
- `〜やけん`: 理由・根拠の意味が強いため v0.1 では構文化しない
- `〜っちゃ`: 言語名・会話・REPL・エラーメッセージ等に残し、汎用予約語にはしない

というように、自然言語としての意味とプログラム上の意味が無理なく重なる範囲だけを使います。

### 2. 曖昧さを許すか

自然な日本語・方言に近づけるほど曖昧さが増えます。

Pyccha v0.1 では、自然文を幅広く解釈するより **少数の厳密な構文** を優先します。

表記ゆれや別の言い回しを許容するかは、最初の parser / transpiler が動いてから検討します。

### 3. Python との距離

初期版では Python をバックエンドとして利用しますが、Python の全機能を方言化することは目的にしません。

Pyccha 独自の小さな言語として成立させ、必要に応じて Python の機能へ橋を架ける方向を想定しています。

名称は **Pyccha（ぱいっちゃ）** に変更しました。由来は Python の `Py` と北九州弁の「〜っちゃ」です。名称自体に `Python` を含めないため、旧称 `Pythoncha` で懸念していた「別言語名に Python 商標を直接含める」問題は大きく後退しました。Python Software Foundation 公式・公認と誤認させる表現や Python ロゴの改変利用は避けます。PyPI 上の `pyccha`、CLI 名、既存プロジェクトとの衝突は初回公開直前に再確認します。
