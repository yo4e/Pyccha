# Pyccha v0.1 文法ワークベンチ

この文書は **決定済み仕様ではない**。

北九州弁としての事実・自然さは [北九州弁ノート](../dialect/kitakyushu.md) を参照し、この文書では「それをプログラミング言語としてどう使うか」を検討する。まず方言ノートの **v0.1 基本語彙表** を埋め、必要な項目だけ個別設計へ進む。

## 原則

1. 方言の単語を Python keyword に1対1で置換しない。
2. 北九州弁として不自然なら、便利でも採用しない。
3. 自然文を何でも受理する言語にはしない。
4. v0.1 は少数の厳密な構文だけ持つ。
5. 方言ノート側が修正されたら、こちらの案も再検討する。

## G002 代入

**参照**: D008

現時点の第一候補:

```text
名前 = "山田"
```

方言化のためだけに文章へ伸ばさず、代入は `=` を残す案を優先する。

## G003 条件分岐

**参照**: D003, D006, D007

候補:

```text
もし 名前が "山田" やったら
    "本人っちゃ" っちゆう
ちごうたら
    "誰なん？" っちゆう
おしまい
```

未決定事項:

- `もし` は必要か。
- `名前が "山田"` の `が` を構文として扱うか。
- else相当は `ちごうたら` が自然か。
- block終端を `おしまい` にするか。

## G004 繰り返し

**参照**: D009

現時点の候補:

```text
3回くりかえす
    "まだやるん？" っちゆう
おしまい
```

「繰り返す」はひらがなで `くりかえす` とする候補。

---

## G005 「やけん」

**参照**: D002

まだ構文を決めない。

理由表現として自然な用例を方言ノート側で集めてから、以下のどれに近いかを判断する。

- 条件
- guard
- 前提
- 理由付き実行
- 文法化せず、別の用途にする

**禁止事項**: 調査前に `やけん = if` と固定しない。

---

## G006 「っちゃ」

**参照**: D001

まだ構文を決めない。

候補:

- 断定
- 文終端
- 出力結果の装飾
- REPLの返答
- 構文には使わず言語名・エラーメッセージ等に留める

方言としての実際のニュアンスを先に確定する。

---

## G007 論理演算

**参照**: D016, D017, D018

現時点の候補:

```text
A それと B
A か B
A やない
```

- AND: `それと`
- OR: `か`
- NOT: `やない`

`か` は疑問表現とも重なるため、parser上の曖昧性は実装前に確認する。
