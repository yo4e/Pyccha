# Pyccha v0.1 文法ワークベンチ

この文書は、北九州弁ノートとコード標本の確認結果をもとに、Pyccha v0.1 の最初の parser / transpiler が受け付ける構文を整理する。

北九州弁としての事実・自然さは [北九州弁ノート](../dialect/kitakyushu.md) を優先し、実際の語感確認は [v0.1 コード標本集](examples-v0.1.md) を参照する。

## v0.1 の設計状態

2026-09-29 の標本レビューで、最初の Lark grammar を実装できる程度まで構文を絞った。

ここで「採用」とするのは **Pyccha v0.1 の設計判断** であり、すべてが自然会話そのものだという意味ではない。

## 原則

1. 方言の単語を Python keyword に1対1で置換しない。
2. 北九州弁として不自然なら、便利でも採用しない。
3. 自然文を何でも受理する言語にはしない。
4. v0.1 は少数の厳密な構文だけ持つ。
5. 方言化すると不自然な演算は、記号のまま残してよい。
6. インデントは可読性のために使うが、v0.1 の block 構造は明示語で閉じる。

## G001 標準出力

**参照**: D005

```text
"こんにちは" っちゆう
名前 っちゆう
```

v0.1 は `<式> っちゆう` を標準出力構文とする。

`〜っちゆう` を自然言語の意味そのままで `print` と同一視するのではなく、引用・発話の語感を借りた Pyccha 独自構文として扱う。

---

## G002 代入

**参照**: D008

```text
名前 = "山田"
個数 = 3
```

代入は `=` を残す。

自然文に寄せるためだけに `〜にする` 等へ伸ばさない。

## G003 条件分岐

**参照**: D003, D006, D007

```text
もし 名前 == "山田" やったら
    "本人っちゃ" っちゆう
ちごうたら
    "誰なん？" っちゆう
おしまい
```

### 決定

- `もし` は v0.1 では必須。
- 条件節の末尾は `やったら`。
- else は `ちごうたら`。
- if block は `おしまい` で閉じる。
- インデントは推奨するが、最初の parser では構文意味を持たせない。

`もし` を必須にするのは自然会話上の必須性ではなく、parser と読み手の両方に条件節の開始を明示するため。

## G004 繰り返し

**参照**: D009

```text
3回くりかえす
    "まだやるん？" っちゆう
おしまい
```

### v0.1 の範囲

- 最初は整数リテラルによる回数指定だけでよい。
- `くりかえす` はひらがな表記。
- repeat block も `おしまい` で閉じる。
- `while` 相当、iterator、range 表現は後回し。

## G005 比較

**参照**: D010, D011, D012, D013

### 等値 / 非等値

```text
名前 == "山田"
名前 != "佐藤"
```

`〜と同じ / 〜と違う` を予約語化すると説明文っぽくなりすぎるため、v0.1 は `== / !=` を使う。

### 大小比較

```text
年齢が 20 よりでかいん
残りが 3 よりこまいん
```

条件節では次のようにつなぐ。

```text
もし 年齢が 20 よりでかいん やったら
もし 残りが 3 よりこまいん やったら
```

### 「〜ん」の扱い

`〜ん` を条件式全体へ機械的に追加する規則にはしない。

v0.1 では、少なくとも以下の述語形の一部として扱う。

- `よりでかいん`
- `よりこまいん`
- `やないん`

つまり `〜ん` は独立 keyword ではなく、自然な接続を作るための述語側の形として parser に落とす。

## G006 論理演算

**参照**: D016, D017, D018

### AND

```text
A それと B
```

### OR

```text
A か B
```

### NOT

```text
A やないん
```

### 優先順位

v0.1 は次の順を想定する。

1. 比較・原子的な条件
2. `やないん`
3. `それと`
4. `か`

`か` は疑問終助詞としての用途を v0.1 へ同時導入せず、`もし ... やったら` の条件式内部では OR として意味を固定する。

`やないん` は Python の前置き `not` を単純置換しない。最初は名前や単純な原子的条件への後置否定に限定する。

## G007 真偽値

**参照**: D014, D015

`ほんとやん / うそやん` は v0.1 の入力リテラルにはしない。

理由:

- 値そのものというより、反応・断定としての語感が強い。
- `営業中 = ほんとやん` のように置くと、コード中では会話調が過剰になる。
- 比較演算だけで最初の parser / transpiler を成立させられるため、今ここで真偽値リテラルを決める必要がない。

将来候補:

- REPL の評価結果
- 診断メッセージ
- エラーメッセージ
- 別の中立的な真偽値リテラル

## G008 「やけん」

**参照**: D002

v0.1 の予約語にはしない。

`やけん` は理由・根拠を表す語なので、`if` の別名にすると意味がずれる。

将来、reason / guard / 前提付き実行など、自然な意味対応が見つかった場合だけ再検討する。

## G009 「っちゃ」

**参照**: D001

v0.1 の汎用予約語にはしない。

候補として残す場所:

- 言語名
- 文字列中の会話
- REPL の返答
- 方言らしい診断・エラーメッセージ

断定、代入、出力、文終端のどれかへ無理に固定しない。

## Lark 実装へ渡す最小文法イメージ

これはまだ `.lark` ファイルそのものではなく、実装時の境界を明確にするための擬似文法。

```text
program      := statement*

statement    := assignment
              | output
              | if_stmt
              | repeat_stmt

assignment   := NAME "=" expr
output       := expr "っちゆう"

if_stmt      := "もし" condition "やったら"
                statement*
                ("ちごうたら" statement*)?
                "おしまい"

repeat_stmt  := INT "回くりかえす"
                statement*
                "おしまい"

condition    := disjunction

disjunction := conjunction ("か" conjunction)*
conjunction := negatable ("それと" negatable)*
negatable    := comparison
              | NAME "やないん"

comparison   := expr "==" expr
              | expr "!=" expr
              | expr "が" expr "よりでかいん"
              | expr "が" expr "よりこまいん"

expr         := STRING | NUMBER | NAME
```

### 実装時に守る境界

- v0.1 で自然言語一般を parse しようとしない。
- `やけん` と構文上の `っちゃ` は入れない。
- 真偽値リテラルを無理に追加しない。
- INDENT / DEDENT 処理は最初の slice では不要。`おしまい` を構造上の終端に使う。
- `それと` は `か` より強く結合する。
- source map / 行番号を後で診断へ使えるよう、Lark の位置情報は保持する。
