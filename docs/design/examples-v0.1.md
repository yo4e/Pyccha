# Pyccha v0.1 コード標本集

この文書は **まだ動かないPycchaコードを並べて、語感と文法の違和感を見つけるための標本集** です。

ここにあるコードは仕様ではありません。むしろ、読んで「これは変」「こっちの言い方のほうが自然」と直すための材料です。

北九州弁そのものの記録は [北九州弁ノート](../dialect/kitakyushu.md)、文法候補は [v0.1 文法ワークベンチ](grammar-v0.1.md) を参照します。

## 見方

各標本には次を付けます。

- **ねらい**: 何を試しているか
- **コード**: 仮のPyccha
- **見るところ**: 語感・構文として違和感が出そうな箇所
- **判定**: 未確認 / 直したい / だいたいよい / 採用候補

山田さんは、コードそのものを直接書き換えてかまいません。

## E001 まず一言しゃべる

**ねらい**: 最小の出力構文。

```text
"こんにちは" っちゆう
```

**見るところ**:

- `っちゆう` をプログラム末尾に置いた感じは自然か。
- 引用符つき文字列との並びに違和感がないか。

**判定**: 未確認

## E002 変数を作ってしゃべる

**ねらい**: 代入は無理に方言化せず `=` を残す。

```text
名前 = "山田"
名前 っちゆう
```

**見るところ**:

- 変数をそのまま `っちゆう` の前に置けるか。
- `=` だけ急に記号でも気にならないか。

**判定**: 未確認

## E003 条件分岐

**ねらい**: `もし〜やったら / ちごうたら / おしまい` の並びを読む。

```text
名前 = "山田"

もし 名前が "山田" やったら
    "本人っちゃ" っちゆう
ちごうたら
    "誰なん？" っちゆう
おしまい
```

**見るところ**:

- `もし` は本当に要るか。
- `名前が "山田"` は自然か、それとも別の比較表現がよいか。
- `ちごうたら` が else の位置に単独で立つと自然か。
- `おしまい` を構文語として読むとどう感じるか。

**判定**: 未確認

- `3回` だけでも意味が十分か。
- `おしまい` との組み合わせ。

## E005 でかい / こまい

**ねらい**: 大小比較を文章に入れてみる。

```text
年齢 = 22

もし 年齢が 20 よりでかい やったら
    "大人やん" っちゆう
おしまい
```

```text
残り = 2

もし 残りが 3 よりこまい やったら
    "もうちょいやん" っちゆう
おしまい
```

**見るところ**:

- `年齢が 20 よりでかい やったら` はかなり人工的に見えるか。
- `やったら` を比較文へどう接続するのが自然か。
- `よりでかい / よりこまい` 自体は気持ちよく読めるか。

**判定**: 未確認

## E006 真偽値

**ねらい**: `ほんとやん / うそやん` を値として置いてみる。

```text
営業中 = ほんとやん
売り切れ = うそやん
```

**見るところ**:

- 会話としては自然でも、値として置くと変ではないか。
- `ほんとやん` と `うそやん` は対になって見えるか。
- 真偽値だけは `true / false` のほうがよい可能性もある。

**判定**: 未確認

---

## E007 AND

**ねらい**: `それと` を論理ANDとして読む。

```text
晴れ = ほんとやん
休み = ほんとやん

もし 晴れ それと 休み やったら
    "出かけよ" っちゆう
おしまい
```

**見るところ**:

- `A それと B` は論理結合として自然か。
- `それと` が単なる列挙に見えないか。
- 条件の末尾に `やったら` が来ることで意味がまとまるか。

**判定**: 未確認

---

## E008 OR

**ねらい**: `か` を論理ORとして読む。

```text
飲み物 = "コーヒー"

もし 飲み物が "コーヒー" か 飲み物が "お茶" やったら
    "どっちも好き" っちゆう
おしまい
```

**見るところ**:

- `A か B` はかなり自然だが、疑問の `か` と混同しないか。
- 条件文として長くなったときも読みやすいか。

**判定**: 未確認

---

## E009 NOT

**ねらい**: `やない` を否定として使う。

```text
雨 = うそやん

もし 雨 やない やったら
    "傘いらんやん" っちゆう
おしまい
```

**見るところ**:

- `雨 やない やったら` は不自然か。
- 真偽値変数そのものを否定する構文として、別の語順が必要か。
- `やない` は比較否定のほうが自然か。

**判定**: 未確認

## E010 等しい / 違う

**ねらい**: 標準語仮置きの比較を実際の文にする。

```text
名前 = "山田"

もし 名前が "山田" と同じ やったら
    "そうそう" っちゆう
おしまい
```

```text
もし 名前が "佐藤" と違う やったら
    "佐藤さんやない" っちゆう
おしまい
```

**見るところ**:

- `と同じ / と違う` を使うと説明文っぽくなりすぎないか。
- 単純比較だけ `== / !=` を残すほうがよいか。
- `が` と比較句の組み合わせ。

**判定**: 未確認

## E011 コメント

**ねらい**: コメントは方言化しない。

```text
# あとで名前は変える
名前 = "山田"

"こんにちは" っちゆう
```

**見るところ**:

- `#` が混ざっても世界観を壊さないか。
- コメントまで日本語構文を作る必要はなさそうか。

**判定**: 採用候補

## E012 「やけん」をどこに置くか

**ねらい**: `やけん` は用途未決定なので、複数案を並べて比べる。

### 案A: 理由を先に置く

```text
雨が降っとるやけん
    "傘持っていき" っちゆう
おしまい
```

### 案B: 理由を後ろへ置く

```text
"傘持っていき" っちゆう
雨が降っとるやけん
```

### 案C: 文法化しない

`やけん` はPycchaの予約語にはせず、文字列やエラーメッセージ等でだけ使う。

**見るところ**:

- どの語順が北九州弁として自然か。
- そもそも `やけん` を制御構文にする必要があるか。
- 条件 `やったら` と役割が競合しないか。

**判定**: 未確認

## E013 「っちゃ」をどこに置くか

**ねらい**: Pycchaらしさの象徴だが、構文へ無理に入れない。

### 案A: 文字列の中だけ

```text
"本人っちゃ" っちゆう
```

### 案B: 断定として使う

```text
名前は "山田" っちゃ
```

### 案C: 構文には使わない

言語名やREPL、エラーメッセージにだけ使う。

**見るところ**:

- 実際の `〜っちゃ` のニュアンスと合うか。
- 予約語にすると、急に「なんちゃって方言」感が出ないか。

**判定**: 未確認

## E014 小さなまとめ例

**ねらい**: 今ある候補を一度に読んで、全体のリズムを見る。

```text
# 今日のおやつ
おやつ = "シロヤ"
個数 = 3
お腹すいた = ほんとやん

もし お腹すいた それと 個数が 0 よりでかい やったら
    3回くりかえす
        おやつ っちゆう
    おしまい
ちごうたら
    "今日はなし" っちゆう
おしまい
```

**見るところ**:

- 1行ずつは読めても、まとまると不自然になる箇所はないか。
- `それと`、`よりでかい`、`やったら` の接続。
- `おしまい` がネストしたとき分かりやすいか。
- インデントがあるなら、そもそも `おしまい` が必要か。

**判定**: 未確認
